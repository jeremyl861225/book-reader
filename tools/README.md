# 轉檔工具

把一本書的章節 PDF 轉成 Book reader 可以匯入的檔案。兩個步驟：

```bash
pip install pymupdf                                  # 唯一相依

python3 tools/convert.py "<書的資料夾>" packs/        # ① PDF → 內容包（可中斷續轉）
python3 tools/make_book.py packs/ "書名" out/        # ② 內容包 → 書籍檔
```

把 `out/` 整包用 AirDrop、雲端硬碟或隨身碟傳到裝置，在 app 的
「設定 → 書籍管理 → 匯入書籍檔」**一次全選**匯入。

> ⚠️ **書的內容不要進版控。** 這個 repo 是公開的，`packs/` 與 `*.book.json`
> 都只該留在本機。要跨裝置就用上面的方式自己搬運，不要放雲端 repo。

## ① convert.py：PDF → 內容包

### 輸入結構

可以吃整本書的根資料夾、單一 Section 資料夾，或單一 PDF。整本書的資料夾長這樣：

```
<書的資料夾>/
├── 00 - 前言.pdf                    ← 根目錄零散檔（編號 0 或 99）
├── 99 - 索引.pdf
├── 01 - SECTION I - 章標題/          ← 資料夾編號＝章，資料夾名＝章標題
│   ├── CH001 - 節標題.pdf            ← CHnnn 的 nnn ＝節編號
│   └── CH002 - 節標題.pdf
└── 02 - SECTION II - 章標題/
```

沒有編號的資料夾會被略過（可以把自己的筆記、摘要放在那裡不受影響）。
也支援中文命名：`第1章第2節 標題.pdf`、`1-2 標題.pdf`。

### 輸出

每個 PDF 產生一個同名 `.json`：

```json
{"app": "book-reader-pack",
 "sections": [{"chapter": 1, "chapterTitle": "…", "section": 35, "title": "…",
               "paras": ["段落字串", {"img": "data:image/jpeg;base64,…", "caption": "可選"}]}]}
```

**已存在的檔案會跳過**，所以中斷後重跑會從上次的地方接續。
要重轉某幾章就先把那幾個 `.json` 刪掉。

參數：`--max-width=1200`（圖片寬度上限）、`--quality=78`（JPEG 品質）。

### 斷段邏輯（改壞了整本書都會難讀，動之前先讀這段）

初版是「行尾出現句尾標點就切段」——但 PDF 的換行位置是排版決定的，
句子結尾剛好落在行尾純屬巧合，等於在隨機位置切句子（實測有 22% 的段落是句子中段）。

現行做法：

- **段落結束 ＝ 句尾標點 ＋ 該行明顯短於區塊右邊界**（`SHORT_LINE_RATIO = 0.06`）。
  滿行代表這句話還會續到下一行
- **段落可跨區塊、跨頁接續**：區塊結束時句子還沒完就先留著，接到下一個區塊
- **縮寫不算句尾**：`ABBR_END` 擋掉 `Fig.` `Figs.` `Table.` `e.g.` `et al.` 等，
  否則「… ( Figs.」會被切開，圖號掉到下一段
- **用字級分離標題與圖說**：全文最常見的字級＝內文字級；
  和內文差 >0.5 的區塊自成一段，不與前後文合併
- **圖片延後插入**：段落進行到一半遇到插圖，先暫存，等段落收完再放，避免圖片把句子切斷
- **空白正規化**：`\xa0` 轉一般空白、句點後補空白——
  漏了這步，全文搜尋會搜不到跨行的詞

### 圖片：判斷有沒有漏圖要看「像素」，不要看「位元組」

`MIN_IMG_PX = 60` 會擋掉小於 60×60 的圖。這個門檻很重要，因為書裡常有
出版社的裝飾小圖——**13×16 像素的小圖也可能有 11 KB**，
所以用檔案大小統計「PDF 裡有幾張圖」會虛胖，看起來像漏了一半。
要核對擷取率，一律用像素尺寸當基準。

`MIN_IMG_BYTES = 3000` 是先擋掉明顯的雜訊，不是判斷依據。

## ② make_book.py：內容包 → 書籍檔

```bash
python3 tools/make_book.py packs/ "書名" out/ [--part-mb=20] [--key=自訂識別碼]
```

輸出 `<書名>-1ofN.book.json`（只有一份時是 `<書名>.book.json`）。
格式規格見專案根目錄的 [README](../README.md#書籍檔格式bookjson)。

兩個重點：

- **同一本書的每一份 `book.key` 必須相同**，app 匯入時靠它把多份合併成一本書。
  預設由書名產生；書名改了又要接續同一本，就用 `--key=` 指定原本的值
- **大書一定要拆份**。手機解析單一過大的 JSON 會失敗，
  不要為了「只有一個檔案比較乾淨」而把 `--part-mb` 調得很大

`highlights` 在這裡固定是空陣列——螢光筆與筆記是 app 匯出時才會帶上的。

## 品質抽查（別轉完整本才檢查）

先挑 3 章代表性的來轉：一般章節、圖最多的章節、篇幅最長的章節。檢查：

1. **頁首頁尾雜訊**：有些書每頁有 running header（書名、頁碼）。
   如果段落裡混進重複的雜訊行，要在 `convert_pdf()` 加過濾
   （例：同一行在 >30% 的頁面出現就移除，或按 y 座標排除頁面頂／底 5% 的短行）。
   不是每本書都需要——header 若不在文字層就完全不會有這個問題，先驗證再決定要不要寫
2. **段落品質**：抓兩個指標——以縮寫結尾的段落數（應為 0）、
   開頭是小寫字母的段落數（剩下的通常是參考文獻和編號清單，那是正常的）
3. **圖片**：張數對得上（用像素基準）、位置在相關文字附近、沒有大量重複的裝飾圖
4. **檔案大小**：單章建議 < 3 MB。過大就調 `--max-width=1000 --quality=70`，
   但圖多的書要留意：這樣只省約 15%，卻會讓圖上的細小標註變糊

確認沒問題再全量跑，最後核對章節數與編號有沒有缺漏。
